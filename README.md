# MoneyFlow — сімейний бюджет

Статичний сайт на GitHub Pages, який пише у звичайну Google Таблицю
через Google Apps Script. Без сервера, без бази даних, без підписки.

```
Браузер (index.html + ES-модулі)
        │  POST  text/plain  (без OAuth)
        ▼
Google Apps Script  «Web App»
        │  SpreadsheetApp
        ▼
Google Таблиця  ·  Transactions · Categories · Users
```

## Що вміє

- **Ввід витрат і доходів** — сума, категорія, дата, нотатка.
  Сума приймає вираз: `120+80+50` або `1250/2`.
- **Кожен записує під себе** — код доступу окремий у кожного,
  ім'я підставляє сервер. Поля «Хто» у формі немає.
- **Підсумки місяця** — баланс, витрати, доходи, середнє за день,
  прогноз на кінець місяця, динаміка до попереднього, розподіл витрат.
- **Ліміти по категоріях** — прогрес-бар, «залишилось X грн,
  на день можна Y грн», попередження за 80% і підсвічування перевищення.
- **Історія** — операції за обраний місяць, з видаленням.
- **Стійкість** — запис, який не вдалося відправити, потрапляє в чергу
  у `localStorage` і докладається сам при поверненні мережі.
  Стан черги завжди видно в шапці.
- **Інтерфейс підлаштовується** — на телефоні розділи розкрипаються
  в таби, на комп'ютері картки можна згортати; вибір запам'ятовується.

## Запуск

Адреса бекенда **не лежить у репозиторії**. Вона підставляється з
`tools/local-endpoint.txt`, який теж у `.gitignore`.

Створіть цей файл — один рядок з адресою вашого Web App:

```
https://script.google.com/macros/s/…/exec
```

Далі двічі клацніть **`start.cmd`**: сервер підніметься, створить
`assets/js/generated/env.js` і відкриє браузер.

> Чому сервер, а не просто відкриття `index.html`: сайт написаний на
> ES-модулях, а браузер блокує їх при протоколі `file://`. Це обмеження
> є лише під час локальної розробки — на GitHub Pages сайт віддається
> по HTTPS і працює без сервера.

Змінити порт або не відкривати браузер:

```powershell
powershell -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8080 -NoBrowser
```

Якщо `tools/local-endpoint.txt` немає, сайт покаже екран
«Не вказано адресу бекенда» з інструкцією, а не мовчки не працюватиме.

## Крок 1. Підготувати Google Таблицю

1. Створіть нову таблицю на Google Диску, назвіть, наприклад, `MoneyFlow`.
2. Відкрийте **Розширення → Apps Script**.
3. Вставте в редактор вміст файлу [`tools/bootstrap-sheets.gs`](tools/bootstrap-sheets.gs).
4. У самому файлі заповніть `DEMO_USERS` — ім'я, колір аватарки
   та **свій код доступу** для кожного:

   ```js
   const DEMO_USERS = [
     { name: 'Я',       color: '#2563eb', accessToken: 'grivna-2026' },
     { name: 'Дружина', color: '#db2777', accessToken: 'kvitka-2026' },
   ];
   ```

   Код не генорується — ви задаєте його самі й запам'ятовуєте.
5. У списку функцій виберіть `bootstrapSheets` і натисніть **Запустити**.

Скрипт створить три аркуші:

| Аркуш | Призначення |
|---|---|
| `Transactions` | усі операції; `ID, Дата, Тип, Категорія, Сума, Користувач, Нотатка, Записано` |
| `Categories` | каталог категорій; `Назва, Тип, Іконка, Колір, Ліміт, ₴` |
| `Users` | `Ім'я, Колір, Сіль, Код доступу` |

Після цього видаліть `bootstrap-sheets.gs` із редактора.

### Як додати користувача

У редакторі Apps Script виконайте одну з функцій:

```
registerUser('Оля', '#7c3aed', 'oliia-2026');   // додати людину
resetUserAccessToken('Оля', 'novyi-kod');       // замінити її код
removeUser('Оля');                              // прибрати доступ
```

`resetUserAccessToken` генерує нову сіль, тож старий хеш більше
не підходить навіть комусь, хто його бачив.

⚠️ Після `bootstrapSheets` відкриті коди лишаються в тексті скрипта.
Це краще за таблицю, але не ідеал — не давайте доступ до проєкту
Apps Script стороннім.

### Як додавати категорії та ліміти

У аркуші `Categories` додайте рядок:

| Назва | Тип | Іконка | Колір | Ліміт, ₴ |
|---|---|---|---|---|
| Спорт | Витрата | 🏋️ | `#7c3aed` | 2000 |

- **Тип** — `Витрата` або `Дохід`. Визначає, в якій групі категорія
  з'явиться у формі.
- **Ліміт, ₴** — `0` або порожнє означає «без ліміту».

## Крок 2. Розгорнути бекенд

У тому ж проєкті Apps Script (після видалення bootstrap-файлу):

1. Вставте вміст файлу [`apps-script/Code.gs`](apps-script/Code.gs).
2. Збережіть.
3. **Розгорнути → Нове розгортання**, тип **Веб-застосунок**.

   | Параметр | Значення | Чому саме так |
   |---|---|---|
   | Execute as | **Me (власник)** | скрипт завжди має права власника, Google не вимагає OAuth від відвідувача |
   | Who has access | **Anyone** | щоб запит із браузера проходив без входу в акаунт |

   > Чому не «User accessing the web app»? Той режим вимагає, щоб
   > відвідувач був залогінений у Google-акаунт, і `fetch` без
   > OAuth-редиректу отримує `401`. А `Session.getActiveUser()` через
   > CORS-запит повертає порожній email.

4. Натисніть **Розгорнути**, підтвердіть дозволи, скопіюйте **URL веб-застосунку**.

## Як влаштована авторизація

У кожної людини свій код доступу, і саме він визначає, від чиєї імені
йде запис.

```
Клієнт                                  Сервер
──────                                  ──────
код у полі входу  ──── POST ────▶  шукаємо рядок у `Users`,
                                 у якому SHA-256(сіль + код)
                                 збігається з поданим
                                            │
                      ◀─── viewer: { name, color } ───┘
```

Три наслідки, які варто розуміти:

**У таблиці немає паролів.** Зберігається `SHA-256(сіль + код)`, а не сам
код. Тому хто має доступ до таблиці — не може витягнути чужі коди й
увійти під їхніми іменами.

**Підробити «Хто» неможливо.** Поле користувача не приходить від клієнта
взагалі — сервер підставляє ім'я сам.

**Код не потрапляє в URL.** Усі запити, включно з читанням, ідуть
методом `POST`. У query string код біз потрапив би в логи Google,
в історію браузера і в заголовок `Referer`.

**Короткий код можна підібрати — перебір зупиняється.** Після 5 невдалих
спроб поспіль вхід блокується на 15 хвилин. Лічильник живе в
`PropertiesService` і переживає перезапуск скрипта.

Блокування перевіряється **до** будь-якого порівняння хешів, тому
після спрацювання відсікаються всі запити — включно з правильним кодом:

| | Спроб на добу |
|---|---|
| Без блокування | ~144 000 |
| Із блокуванням | **480** |

Зменшення у 300 разів: за тиждень автоматичний підбір не встигає нічого.

Лічильник спільний на всіх, а не на користувача: до перевірки ще невідомо,
чий код намагаються ввести. Побічний ефект теж корисний: якщо раптом
ніхто з сім'ї не може увійти, значить або хтось систематично помиляється,
або до таблиці стукає сторонній.

Кнопка на екрані входу стає неактивною і показує зворотний відлік.
Константи — `MAX_FAILED_ATTEMPTS` і `LOCKOUT_DURATION_MINUTES`
на початку `Code.gs`.

**Довжина коду все одно важлива.** Блокування робить перебір безнадзвичайно
повільним, але не неможливим:

| Код | Час перебору |
|---|---|
| `123456` | ~6 днів |
| `12345678` | ~2 роки |
| `grivna-2026` | непрораховано довго |

Тому код має бути довгим і не словниковим.

### Про додаткове шифрування

Ідея «зашифрувати код перед відправкою» тут не додає безпеки, і ось
чому: будь-який ключ, яким шифрує браузер, лежить у тому ж публічному
JavaScript на GitHub Pages. Але «підписаний JWT» стискається на користувача:
підписати може той, у кого є секретний ключ, а браузер його не має.

Реальна межа довіри в цій системі — права на саму таблицю та коди
доступу. Тому замість шифрування зроблено три речі, які справді щось
додають: хешування замість відкритого тексту, передачу кодом посту
замість гет-параметра, і можливість відкликати доступ одній людині,
не ламаючи іншим.

## Публікація на GitHub Pages

Адреса бекенда йде через секрет репозиторію, тому в коді її немає.

1. **Settings → Pages → Source: GitHub Actions.**
2. **Settings → Secrets and variables → Actions → New repository secret**
   — ім'я `APPS_SCRIPT_ENDPOINT`, значення — адреса Web App із кроку 2.
3. `git push` у `main`. Workflow [.github/workflows/pages.yml](.github/workflows/pages.yml)
   збере файл `env.js` з секрету й опублікує сайт.

Що це дає і чого ні:

| | |
|---|---|
| URL не потрапить у git-історію | так |
| URL не видно в самому репозиторії | так |
| URL не видно на сторінці github.io | **ні** — там лежить зібраний `env.js` |

Тобто це обфускація від випадкового подиву в репозиторій, а не захист:
будь-що, що бачить браузер, можна дістати з DevTools. Справжній
секрет — коди доступу в аркуші `Users`.

### Чому не приватний репозиторій

GitHub Pages на безкоштовному плані працює лише з **публічними**
репозиторіями. Приватний репозиторій вимагає GitHub Pro або Team.

Публічний репозиторій тут не страшний: у ньому лежить лише код
застосунку. Таблиця, коди доступу і ваші витрати в git не потрапляють.

Якщо публікація не потрібна — зробіть репозиторій приватним і
користуйтеся локально.

### Свій домен

Додайте файл `CNAME` у корінь репозиторію з одним рядком домену.

### Оновлення Web App

Кожного разу, як змінюєте `Code.gs`, потрібно **Розгорнути → Керувати
розгортаннями → редагувати (олівець) → Версія: Нова версія → Розгорнути**.
Інакше зміни не застосуються.

## Структура проєкту

```
start.cmd                    подвійний клік - запуск сервера
index.html                   розмітка: форма, підсумки, ліміти, історія
assets/
  css/
    base.css                 скидання, дизайн-токени, типографіка
    layout.css               сітка, шапка, таби, адаптив
    components.css           картки, поля, кнопки, графіки
  js/
    config.js                налаштування застосунку, ключі сховища
    generated/env.example.js  зразок файлу середовища (реальний у git не йде)
    main.js                  точка входу: життєвий цикл і маршрутизація подій
    core/
      apiClient.js           єдиний шар, що знає про Apps Script
      budgetStore.js         стан застосунку, черга, цикл синхронізації
      localStore.js          безпечна обгортка над localStorage
    domain/
      amountExpression.js    розбір виразу у полі суми
      period.js              календарна математика «РРРР-ММ»
      statistics.js          підсумки, розподіл, історія
      budget.js              ліміти та їхній стан
      formatters.js          єдине місце для Intl-форматування
    ui/
      dom.js                 утиліти над DOM
      entryForm.js           картка вводу
      overviewPanel.js       підсумки місяця
      budgetPanel.js         прогрес-бари лімітів
      transactionList.js     історія операцій
      syncIndicator.js       позначка синхронізації
      accessGate.js          екран входу за кодом
      profileChip.js         хто зараз вів бюджет
      viewSwitcher.js        таби розділів на телефоні
      collapsibleCards.js    згортання карток на комп'ютері
      toast.js               спливаючі повідомлення
apps-script/
  Code.gs                    бекенд: авторизація, читання, запис
tools/
  bootstrap-sheets.gs        одноразова підготовка таблиці
  serve.ps1                  локальний сервер + генерація env.js
  local-endpoint.txt         адреса бекенда локально (у git не йде)
```

Правило, за яким усе розкладено: `ui` ніколи не знає про мережу,
`core` ніколи не знає про DOM, `domain` не знає ні про те, ні про інше.
