# MoneyFlow — сімейний бюджет

Статичний сайт на GitHub Pages, який пише у звичайну Google Таблицю
через Google Apps Script. Без сервера, без бази даних, без підписки.

```
Браузер (index.html + ES-модулі)
        │  POST  text/plain  (без OAuth)
        ▼
Google Apps Script  «Web App»
        │  SpreadsheetApp
        ▼
Google Таблиця  ·  Transactions · Categories · Users
```

> Рішення, які стоять за архітектурою, чому обрано саме такий варіант і
> що вже перевірялося тестами, описані окремо в **[AGENT.md](AGENT.md)**.

## Що вміє

- **Ввід витрат і доходів** — сума, категорія, дата, нотатка.
  Сума приймає вираз: `120+80+50` або `1250/2`.
- **Кожен записує під себе** — логін і пароль окремі в кожного,
  ім'я підставляє сервер. Поля «Хто» у формі немає.
- **Пароль не залишає браузера** — на сервер іде лише хеш, а браузер
  тримає підписаний сервером токен на тиждень.
- **Підсумки місяця** — баланс, витрати, доходи, середнє за день,
  прогноз на кінець місяця, динаміка до попереднього, розподіл витрат.
- **Ліміти по категоріях** — прогрес-бар, «залишилось X грн,
  на день можна Y грн», попередження за 80% і підсвічування перевищення.
- **Історія** — операції за обраний місяць, з видаленням.
- **Стійкість** — запис, який не вдалося відправити, потрапляє в чергу
  в `localStorage` і докладається сам при поверненні мережі.
  Стан черги завжди видно в шапці.
  Черга належить конкретній людині, а не браузеру: записи, зроблені
  під одним логіном, не можуть потрапити в таблицю від імені іншого.
  Вичерпаний термін сесії не викидає чергу — запис дочекається наступного
  входу. Решта відмов (вимкнули акаунт, змінили пароль) чергу прибирають:
  повторний вхід їх не виправить.
- **Інтерфейс підлаштовується** — на телефоні розділи розкрипаються
  в таби, на комп'ютері картки можна згортати; вибір запам'ятовується.

## Запуск

Адреса бекенда **не лежить у репозиторії**. Вона підставляється з
`tools/local-endpoint.txt`, який теж у `.gitignore`.

Створіть цей файл — один рядок з адресою вашого Web App:

```
https://script.google.com/macros/s/…/exec
```

Далі двічі клацніть **`start.cmd`**: сервер підніметься, створить
`assets/js/generated/env.js` і відкриє браузер.

> Чому сервер, а не просто відкриття `index.html`: сайт написаний на
> ES-модулях, а браузер блокує їх при протоколі `file://`. Це обмеження
> є лише під час локальної розробки — на GitHub Pages сайт віддається
> по HTTPS і працює без сервера.

Змінити порт або не відкривати браузер:

```powershell
powershell -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8080 -NoBrowser
```

Якщо `tools/local-endpoint.txt` немає, сайт покаже екран
«Не вказано адресу бекенда» з інструкцією, а не мовчки не працюватиме.

## Крок 1. Підготувати Google Таблицю

1. Створіть нову таблицю на Google Диску, назвіть, наприклад, `MoneyFlow`.
2. Відкрийте **Розширення → Apps Script**.
3. Вставте в редактор вміст файлу [`tools/bootstrap-sheets.gs`](tools/bootstrap-sheets.gs).
4. У самому файлі заповніть `DEMO_USERS` — логін, колір аватарки
   та **свій пароль** для кожного:

   ```js
   const DEMO_USERS = [
     { login: 'Я',       color: '#2563eb', password: 'Grivna-2026' },
     { login: 'Дружина', color: '#db2777', password: 'Kvitka-2026' },
   ];
   ```

   Пароль не генерується — ви задаєте його самі й запам'ятовуєте.
5. У списку функцій виберіть `bootstrapSheets` і натисніть **Запустити**.

Скрипт створить три аркуші:

| Аркуш | Призначення |
|---|---|
| `Transactions` | усі операції; `ID, Дата, Тип, Категорія, Сума, Користувач, Нотатка, Записано` |
| `Categories` | каталог категорій; `Назва, Тип, Іконка, Колір, Ліміт, ₴` |
| `Users` | `Ім'я, Колір, Пароль, Активний` |

Порядок колонок у `Users` неважливий: сервер пише за підписами,
а не за позиціями.

Після цього видаліть `bootstrap-sheets.gs` із редактора.

### Як додати користувача

У редакторі Apps Script виконайте одну з функцій:

```
registerUser('Оля', '#7c3aed', 'Oliia-2026');   // додати людину
resetUserPassword('Оля', 'Nova-Parily');       // замінити її пароль
removeUser('Оля');                              // прибрати доступ
checkUsersIntegrity();                          // перевірити, чи всі рядки заповнені
```

`resetUserPassword` одразу завершує всі сесії цієї людини: у токені
є час видачі, а сервер порівнює його з часом зміни пароля.

⚠️ Після `bootstrapSheets` відкриті паролі лишаються в тексті скрипта.
Це краще за таблицю, але не ідеал — не давайте доступ до проєкту
Apps Script стороннім. Після першого входу рядки можете стерти.

**Паролі не генеруються і не показуються повторно.** Тому після
`bootstrapSheets` варто одразу виконати `checkUsersIntegrity()` — вона
покаже рядки, де `Пароль` порожній, і такі записи не пропустять вхід.

### Як додавати категорії та ліміти

У аркуші `Categories` додайте рядок:

| Назва | Тип | Іконка | Колір | Ліміт, ₴ |
|---|---|---|---|---|
| Спорт | Витрата | 🏋️ | `#7c3aed` | 2000 |

- **Тип** — `Витрата` або `Дохід`. Визначає, в якій групі категорія
  з'явиться у формі.
- **Ліміт, ₴** — `0` або порожнє означає «без ліміту».

## Крок 2. Розгорнути бекенд

У тому ж проєкті Apps Script (після видалення bootstrap-файлу):

1. Вставте вміст двох файлів:
   - [`apps-script/Code.gs`](apps-script/Code.gs) — операції, знімки, помилки;
   - [`apps-script/auth.gs`](apps-script/auth.gs) — вхід, паролі, сесії, токени.

   Обидва живуть у спільному просторі імен, тому функції з одного
   видно з іншого.
2. Збережіть.
3. **Розгорнути → Нове розгортання**, тип **Веб-застосунок**.

   | Параметр | Значення | Чому саме так |
   |---|---|---|
   | Execute as | **Me (власник)** | скрипт завжди має права власника, Google не вимагає OAuth від відвідувача |
   | Who has access | **Anyone** | щоб запит із браузера проходив без входу в акаунт |

   > Чому не «User accessing the web app»? Той режим вимагає, щоб
   > відвідувач був залогінений у Google-акаунт, і `fetch` без
   > OAuth-редиректу отримує `401`. А `Session.getActiveUser()` через
   > CORS-запит повертає порожній email.

4. Натисніть **Розгорнути**, підтвердіть дозволи, скопіюйте **URL веб-застосунку**.

## Крок 3. Підключити сайт

Створіть файл `tools/local-endpoint.txt` у корені репозиторію й вставте
в нього скопійований URL:

```
https://script.google.com/macros/s/…/exec
```

Далі просто `start.cmd` — сервер сам підставить його у `env.js`.

Готово. Відкрийте сайт і введіть свій логін та пароль. Під час публікації
на GitHub цю адресу передайте через секрет репозиторію.

> Сайт хешує пароль у браузері, а браузери дозволяють це лише на
> захищеному з'єднанні. Локально все працює: `http://localhost`
> вважається захищеним. Якщо відкривати з іншого пристрою — потрібен
> `https://`, тобто задеплоєна на GitHub Pages версія.

## Як влаштована авторизація

У кожної людини свій логін і пароль. Саме вони визначають, від чиєї
особи йде запис.

Пароль **не залишає браузер**. Браузер сам рахує хеш і відправляє
тільки доказ, прив'язаний до миттєвого часу:

```
Клієнт                                  Сервер
──────                                  ──────
логін + пароль
  passwordHash = SHA-256(пароль)        ← це і є «пароль» у системі
  proof = SHA-256(passwordHash + час)
             ──── POST ────▶  шукаємо рядок у `Users` за логіном,
                               рахуємо SHA-256(хеш + той самий час)
                                             │
              ◀─── token, expiresAt ───┘   (підписаний HMAC-SHA256)
```

Далі браузер живе з токеном і більше не має пароля:

```
Клієнт                                  Сервер
──────                                  ──────
sessionToken + action  ──── POST ────▶  перевіряємо підпис і термін,
                                    дістаємо логін із самого токена
                                             │
                       ◀─── snapshot ───────┘
```

Чотири наслідки, які варто розуміти, і п'ятий, який легко пропустити:

**Пароль не передається — ніде й ніколи.** Жодного запиту, в якому є
відкритий пароль: ні при вході, ні при реєстрації. При реєстрації
браузер теж надсилає лише `SHA-256(пароль)`.

**Доказ не переноситься.** Він прив'язаний до часу (±60 хв) і приймається
сервером рівно один раз. Перехоплений запит стає безкорисним, щойно його
вже відіграли.

**У таблиці немає паролів.** Зберігається `SHA-256(пароль)`. Тому хто має
доступ до таблиці — не бачить чужих паролів у відкритому вигляді.

**Підробити «Хто» неможливо.** Поле користувача не приходить від клієнта
взагалі — сервер підставляє ім'я із токена.

**Токен не потрапляє в URL.** Усі запити, включно з читанням, ідуть
методом `POST`. У query string токен потрапляв би в логи Google,
в історію браузера і в заголовок `Referer`.

Чому саме так, а не інакше — у [AGENT.md](AGENT.md#чому-немає-солі).

### Старі схеми не підтримуються

Схема таблиці та формат знімка змінюються без узгодження версій.
Код, який читає два формати одночачі, удвічі складніше перевірити —
а користувач тут один, тож вигода від сумісності нульова.

Тому замість сумісності — **перевірка з голосною помилкою**. Кожен
аркуш має список обов'язкових колонок, і сервер перевіряє його
**до** читання. Перейменування `Сума` у `Transactions` дає:

```
В аркуші Transactions немає стовпців: Сума. Перейменуйте їх у шапці
як у bootstrapSheets — сервер не читає старі схеми.
```

Перевіряються одразу всі відсутні, а не перший — щоб не виправляти
по одному за три заходи. Це навмисно гучніше за тихий зниклий бюджет.

Обґрунтування — [AGENT.md](AGENT.md#немає-зворотної-сумісності).

### Сесія і термін життя

Токен живе тиждень за замовчуванням і зберігається в `localStorage`
браузера. Змінити термін без передеплоювання скрипта можна через
**Файл → Налаштування проекту → Скриптові властивості**:

| Властивість | Типове значення | Що робить |
|---|---|---|
| `moneyflow.tokenSecret` | створюється сам | ключ підпису токенів |
| `moneyflow.tokenTtlHours` | `168` | скільки годин живий токен |

Змінивши `moneyflow.tokenSecret`, усі наявні сесії одразу завершуються —
усі доведеться увійти знові. Це зручний спосіб «вибити» всіх із системи.

`moneyflow.loginState` — службова властивість: там сервер тримає час
останнього прийнятого доказу (щоб не пропустити реплей) і час зміни
пароля (щоб старі токени перестали діяти). Редагувати вручну не треба.

### Перебір паролів

Після 5 невдалих спроб поспіль вхід блокується на 15 хвилин. Лічильник
живе в `PropertiesService` і переживає перезапуск скрипта.

Блокування перевіряється **до** будь-якого порівняння хешів, тому
після спрацювання відсікаються всі запити — включно з правильним паролем:

| | Спроб на добу |
|---|---|
| Без блокування | ~144 000 |
| Із блокуванням | **480** |

Зменшення у 300 разів: за тиждень автоматичний підбір не встигає нічого.

Лічильник спільний на всіх, а не на користувача: до перевірки ще невідомо,
чий пароль намагаються підібрати. Побічний ефект теж корисний: якщо раптом
ніхто з сім'ї не може увійти, значить або хтось систематично помиляється,
або до таблиці стукає сторонній.

Кнопка на екрані входу стає неактивною і показує зворотний відлік.
Константи — `MAX_FAILED_ATTEMPTS` і `LOCKOUT_DURATION_MINUTES`
у [`apps-script/auth.gs`](apps-script/auth.gs).

**Довжина пароля все одно важлива.** Блокування робить перебір безнадзвичайно
повільним, але не неможливим:

| Пароль | Час перебору |
|---|---|
| `123456` | ~6 днів |
| `12345678` | ~2 роки |
| `Grivna-2026` | непрораховано довго |

Тому пароль має бути довгим і не словниковим.

### Справжня межа довіри — права на саму таблицю

Хто має доступ до аркуша `Users`, той бачить хеші й може перебирати
офлайн, поки не знайде пароль. Тому таблиця й не роздається стороннім.
Це не зміниться, поки схема така.

## Що де лежить у браузері

Браузер — найслабше місце системи: усе, що там є, можна прочитати
профілем на чужому або загубленому пристрої. Тому стан розділено
за сховищами відповідно до цінності.

| Сховище | Що в ньому | Чому саме там |
|---|---|---|
| `localStorage` | `moneyflow.session` — токен і логін | має пережити вкладку, інакше доведеться входити щоразу |
| `localStorage` | `moneyflow.pending-entries.<логін>` — черга | втрата черги означала б втрату записів, зроблених без мережі |
| `sessionStorage` | `moneyflow.cached-snapshot` — операції відкритих місяців | закінчує існування разом із вкладкою |
| `localStorage` | вибір місяця, згорнуті картки, зсув годинника | дрібні налаштування, втрата не шкодить |

Ключова річ — операції лежать у `sessionStorage`, а не в `localStorage`.
Закрили вкладку — копії на диску немає, витягнути її з профілю
браузера вже неможливо. При цьому зручність не втрачається: кеш
переживає перезавантаження сторінки, тобто дані на екрані з'являються
миттєво, як раніше.

Другий ключовий момент — у кеші не вся історія, а лише відкриті місяці
(див. нижче). Тому на п'ятирічній історії там у тридцять разів менше,
ніж могло б бути.

Пароль у браузері не зберігається ніде — ні відкрито, ні у вигляді
хеша. На диску лежать лише токен (доки він живий), черга й кеш,
який зникає разом із вкладкою.

## Скільки даних їде через мережу

Браузер тримає не всю історію, а лише ті місяці, які відкривав.
Сервер відповідає тільки на запитані місяці.

Це не оптимізація заради оптимізації. Один запис у родині — це
приблизно 250 байт, тому рівна історія росте швидко:

| період | операцій | повний знімок | зараз |
|---|---|---|---|
| місяць | 150 | 36 КБ | 36 КБ |
| рік | 1 800 | 434 КБ | 36 КБ |
| 5 років | 9 000 | 2.1 МБ | 36 КБ |

Додавання й видалення операції повертають знімок одразу — інакше
довелося б робити другий запит і чекати ще ~3 секунди. Тому без
фільтра кожен введений запис тягнув би з собою всю історію.

**Що це означає на практиці**

- Введення видатків — звичайний запит одного місяця, ~36 КБ.
- Перемикання на старий місяць — один запит, 2–3 секунди.
  Повернення назад уже не коштує нічого: місяці лишаються в пам'яті
  до кінця сесії.
- Поки місяць не прийшов, панелі показують «Завантаження місяця…», а не
  нулі. Нулі виглядали б так, наче в цьому місяці ніхто нічого не витратив.

## Якщо щось зламалося

| Симптом | Причина й що робити |
|---|---|
| «В аркуші Transactions немає стовпців: …» | Перейменували колонку в таблиці. Поверніть назву як у `bootstrapSheets` — або перестворіть аркуш і перенесуть дані. |
| Підсумки порожні, помилок немає | Найімовірніше порожній `Пароль` у рядку `Users`. Запустіть `checkUsersIntegrity()` і задайте пароль через `resetUserPassword`. |
| Змінили `Code.gs` — нічого не змінилось | Не створено нову версію розгортання. Див. «Оновлення Web App». |
| Екран «Не вказано адресу бекенда» | Немає `tools/local-endpoint.txt` або не заданий секрет `APPS_SCRIPT_ENDPOINT`. |
| Екран про незахищене з'єднання | Сайт відкрито не з `localhost` і не з `https://`. Потрібна задеплоєна версія або локальний сервер. |
| Перебір паролів, нікого не пускає 15 хвилин | Лічильник спільний на всіх. Зазвичай достатньо зачекати. Якщо це помилка вашої руки — **Файл → Налаштування проекту → Скриптові властивості**, видаліть `moneyflow.loginAttempts`. |

## Публікація на GitHub Pages

Адреса бекенда йде через секрет репозиторію, тому в коді її немає.

1. **Settings → Pages → Source: GitHub Actions.**
2. **Settings → Secrets and variables → Actions → New repository secret**
   — ім'я `APPS_SCRIPT_ENDPOINT`, значення — адреса Web App із кроку 2.
3. `git push` у `main`. Workflow [.github/workflows/pages.yml](.github/workflows/pages.yml)
   збере файл `env.js` з секрету й опублікує сайт.

Що це дає і чого ні:

| | |
|---|---|
| URL не потрапить у git-історію | так |
| URL не видно в самому репозиторії | так |
| URL не видно на сторінці github.io | **ні** — там лежить зібраний `env.js` |

Тобто це обфускація від випадкового подиву в репозиторій, а не захист:
будь-що, що бачить браузер, можна дістати з DevTools.

### Чому не приватний репозиторій

GitHub Pages на безкоштовному плані працює лише з **публічними**
репозиторіями. Приватний репозиторій вимагає GitHub Pro або Team.

Публічний репозиторій тут не страшний: у ньому лежить лише код
застосунку. Таблиця, хеші паролів і ваші витрати в git не потрапляють.

Якщо публікація не потрібна — зробіть репозиторій приватним і
користуйтеся локально.

### Свій домен

Додайте файл `CNAME` у корінь репозиторію з одним рядком домену.

### Оновлення Web App

Кожного разу, як змінюєте `Code.gs` або `auth.gs`, потрібно
**Розгорнути → Керувати розгортаннями → редагувати (олівець) →
Версія: Нова версія → Розгорнути**. Інакше зміни не застосуються.

Налаштування на кшталт терміну життя токена (`moneyflow.tokenTtlHours`)
редагуються без передеплоювання: **Файл → Налаштування проекту →
Скриптові властивості**.

Порядок деплою клієнта й сервера має значення — див.
[AGENT.md](AGENT.md#порядок-деплою).

```
start.cmd                    подвійний клік - запуск сервера
index.html                   розмітка: форма, підсумки, ліміти, історія
assets/
  css/
    base.css                 скидання, дизайн-токени, типографіка
    layout.css               сітка, шапка, таби, адаптив
    components.css           картки, поля, кнопки, графіки
  js/
    config.js                налаштування застосунку, ключі сховища
    main.js                  точка входу: життєвий цикл і маршрутизація подій
    core/
      apiClient.js           єдиний шар, що знає про Apps Script
      budgetStore.js         стан застосунку, черга, цикл синхронізації
      localStore.js          безпечна обгортка над сховищем браузера
    domain/
      amountExpression.js    розбір виразу у полі суми
      budget.js              ліміти та їхній стан
      crypto.js              SHA-256 у браузері: хеш пароля й доказ входу
      formatters.js          єдине місце для Intl-форматування
      period.js              календарна математика «РРРР-ММ»
      statistics.js          підсумки, розподіл, історія
    ui/
      accessGate.js          екран входу за логіном і паролем
      budgetPanel.js         прогрес-бари лімітів
      collapsibleCards.js    згортання карток на комп'ютері
      dom.js                 утиліти над DOM
      entryForm.js           картка вводу
      overviewPanel.js       підсумки місяця
      profileChip.js         хто зараз вів бюджет
      registrationPanel.js   самостійна реєстрація
      syncIndicator.js       позначка синхронізації
      toast.js               спливаючі повідомлення
      transactionList.js     історія операцій
      viewSwitcher.js        таби розділів на телефоні
    generated/
      env.example.js         зразок файлу середовища (реальний у git не йде)
apps-script/
  appsscript.json            манifest проєкту Apps Script
  Code.gs                    бекенд: операції, знімки, помилки
  auth.gs                    бекенд: паролі, вхід, сесії, підпис токенів
tools/
  bootstrap-sheets.gs        одноразова підготовка таблиці
  serve.ps1                  локальний сервер + генерація env.js

```

Правило, за яким усе розкладено: `ui` ніколи не знає про мережу,
`core` ніколи не знає про DOM, `domain` не знає ні про те, ні про інше.
Обґрунтування — див. [AGENT.md](AGENT.md#шари-і-залежності).
